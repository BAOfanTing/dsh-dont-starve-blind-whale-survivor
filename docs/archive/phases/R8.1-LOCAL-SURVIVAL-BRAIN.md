# R8.1：本地生存大脑（Local Survival Brain）

> 状态：**代码 + fengari 单测已落地；真机长期生存尚未验证**。本阶段只做「高频、确定、有限」的生存维护，不做完整攻略树。

## 1. 定位

把原有 Lua `reflex.lua`（原为「3 秒必死反射」）升级为**游戏内确定性生存行为层**：

- 短周期、高优先级生存决策在 **Lua 本地**做，不等远端 LLM、不等文件桥。
- 外部 LLM 负责长期目标、探索、采集、科技、建家、战斗策略。
- `Planner / TaskBoard` 是长期目标管理，**不是动作执行权限的唯一来源**。
- 所有动作仍走**唯一**状态机 `Whale.actions` → `Dispatcher → Control Lease → Lua Guard → 核验`。

## 2. 优先级调度（单一入口，不各模块自启动作）

| 优先级 | 行为 | 是否可抢占普通任务 |
|---|---|---|
| P0 | 受攻击 / 致命危险 / 夜间完全无光 | 可以 |
| P1 | 夜间火源将熄、严重饥饿（≤30%）、严重低血（<35%）、温度异常 | 满足条件时允许 |
| P2 | 日常添柴（白天）、普通预防性进食、理智维护、光源储备 | 否，仅空闲执行 |
| P3 | 资源储备 / 探索性家务 | 交给 LLM，不在 Reflex 帧循环做 |

实现要点：候选行为评估与执行分离，但**只有一个调度器**（`try_action` + `Whale.actions`），不引入第二条动作通道；所有本地动作走 `cmd_id = "reflex"` 的内部白名单。

## 3. 换手冻结（Lease revoking ↔ Reflex 竞态）

`bridge.lua` 每 tick 顺序：`poll_authority → poll_lease → poll_command → actions.Tick → reflex.Tick`。

新增 `local_action_frozen`：

1. `poll_lease` 观察到 `status == "revoking"` → **先** `FreezeLocalActions` **再** `WriteLeaseAck`（其中调用 `A.Abort` 停旧动作）。
2. 冻结期间：`R.Tick()` 直接返回，不启动任何新动作；`A.Start(cmd_id=="reflex")` 也直接拒绝（防其它路径绕过）。
3. 只有 `poll_authority` 读到**新鲜、合法的非 revoking 权威**才 `UnfreezeLocalActions`。
4. 多次轮询同一 revoking 幂等；绝不为了恢复 Reflex 而绕过 LeaseManager 权威。

## 4. 温度方向性

旧实现「过冷/过热都去找最近火堆并 move_to」是错的。现拆为：

- **过冷（< 5）**：找**点燃的**热源（fueled 非空），靠近；滞回恢复阈值 8。
- **过热（> 65）**：**绝不向火堆移动**（`can_run=false`，只上报 `too_hot_report_only`）；恢复阈值 60。
- 无可读温度/无可靠热源时**不移动**。

## 5. 日常维护（复用现有 JOB，不另造通道）

- **营火燃料**：识别附近火源 `fueled:GetPercent()`；夜间 <35% 记 P1、白天 <20% 记 P2；有燃料物品才执行；通过现有 `JOBS.add_fuel`（`A.Start("add_fuel", {radius})`）**一次一份**；完成后核对 `before/after` 百分比，**未更新则冷却 6s，禁止连续添柴**。
- **进食**：复用 `eatrules.PickBest()`；`<=30%` 为 P1 紧急（可抢占），`30%~50%` 为 P2 **空闲**预防性进食；接近满值不浪费；无安全食物只上报、绝不乱吃怪物肉。
- **理智**：理智 <55% 记需求；**空闲且附近（≤8 格）有花**才 `gather` 采花；没花只上报，不无目标漫游；恢复后清需求。
- **光源**：保留原有「入夜举/做火把、白天有料提前做、火把耗尽重识别、便携光≠站在灯下」；审计了「可制作」与「足够备用」是两种状态（`light_report.can_craft` / `reserve_ok`）。

集中配置：所有阈值/频率集中在 `reflex.lua` 顶部 `CFG` 表（`every=5` 即约 1s 一次；燃料/进食/理智/温度阈值均在此），不再散落硬编码。

## 6. 性能

`TICK=0.2s`，Reflex 每 `CFG.every=5` tick（≈1s）评估一次；温度/饥饿/血量读组件（O(1)）；火源/花朵用 `U.find_nearest` 有界半径（12/8），不做全图扫描。复杂目标评估不进入紧急循环。

## 7. 测试（fengari 真实 Lua）

在 `tests/reflex.test.mjs`（已有 99 项）基础上新增 R8.1 用例，全部跑真实 `reflex.lua`：

- `R81-FREEZE-01` revoking 冻结期不启动动作、`A.Start(reflex)` 被拒、解冻后恢复。
- `R81-TEMP-01` 过热绝不向火堆移动；`R81-TEMP-02` 过冷靠近点燃热源。
- `R81-FUEL-01` 白天低燃料启动一次 `add_fuel`；`R81-FUEL-02` 燃料未更新则冷却内不重复添柴。
- `R81-SANITY-01` 低理智+近花→空闲采花；`R81-SANITY-02` 无花不漫游。
- `R81-FOOD-01` 无安全食物不 eat。
- `R81-PREEMPT-01` P2 维护不抢占模型任务；`R81-PREEMPT-02` P0 夜间无光可抢占模型任务。

## 8. 尚未实现 / 边界（诚实声明）

- 真正的**长期生存**（长程食物补给、营地/季节管理、通用风筝战斗、箱/锅自动化）未包含；需后续阶段补齐。
- 「燃料状态未更新」基于火焰档位/百分比可读性；若客户端读不到精确燃料，只能保守估计（详见 `REFUELING` 思路）。
- **Fengari 单测通过 ≠ 真机生存验证通过**；真机项（LLM 采集中被袭立即逃、模型思考时仍照明进食、加柴不过量、换手不重启动、夏季过热不烤火）需按第 5 节清单在实机复核。
