# M2.2 · 已知限制

> 版本 0.16.0。**只读事实，不美化。**

---

## 1. `pickupables` 只表达"拾取候选"这一种可行动性

本阶段只把"能捡的东西"提升为可行动目标。
"能砍的树""能挖的矿""能采的浆果丛"仍然躺在 `resources` 里 —— 这是**故意的**，
因为砍/挖/采这些动作本阶段没开放，观察层不应该暗示它们可执行。

⇒ 如果将来开放 `chop`/`mine`/`harvest`，需要各自定义候选规则并复用同一套
"观察=执行"共享模块的思路（`pickuprules` 是模板）。

## 2. 白名单仍然只有 3 个 prefab

`twigs` / `cutgrass` / `flint`。`inv_rocks`（石头物品）等仍未核实掉落形态，**未放行**。
`pickupables` 只会出现这三类；地上其他物品（金块、木头、种子……）仍进 `resources`，
并且**捡不了**（`prefab_not_allowed`）。这不是缺陷，是"没核实就不放行"。

## 3. 桶容量没有按桶单独配置

`pickupables` 复用全局单桶上限 12。若某片区域地上有超过 12 件可拾取物，
多出来的不会拿到 `#N`（但会计入 `total_found` 与 `not_returned_count`，文本也会提示桶满）。

**没做**的原因：新增配置项会引入"非数字/越界/兼容"一整类问题，而 12 对首版够用。
如果实测经常撞上限，再单独给 `pickupables` 一个配置项。

## 4. `item_kind` 只在 `pickupables` 上有

其他桶的条目没有这个字段（它们的 `category` 本身就是语义）。
Node 侧渲染目前也不显示 `item_kind`（只用于 JSON 消费方）。

## 5. 截断提示是"桶级"的，不是逐实体

文本只会说"本桶已满，可能还有没列出的"，不会告诉你被截掉的具体是谁
（`delta.not_returned` 有前若干条的摘要，但不是完整列表）。

## 6. 真机样本依赖重进世界（已重载，样本已取到）

Lua 改了就必须重载世界，0.16.0 才会生效。**没重进之前看不到 `pickupables` 桶**
（实测 0.15.1 世界里只有七桶，脚本会如实报 FAIL/NOT_OBSERVED）。

已重载到 0.16.0 并取到样本：`node tools/m2_2_verify_nearby.mjs --bridgeDir <save> --pickup`
→ **14/14 PASS**（详见测试报告 §5）。样本世界里只有 4 个燧石可拾取，
"同一片区域 >12 个可拾取物"这种极端情形仍是 **NOT_TESTED**。

## 6.1 JSON 里 `buckets` 的**键序不保证**

`buckets` 是 Lua 哈希表，编码成 JSON 后键序是 `pairs()` 顺序 —— 真机上实测与设计顺序不同。
**这不是缺陷**：顺序的保证在另外两处，且都已钉住：

- `#N` 编号与截断顺序由 `N.BUCKETS` 决定（Lua 内部 `ipairs`，确定性）；
- 文本渲染：Lua 侧按 `N.BUCKETS`、Node 侧按 `BUCKET_LABELS`，都是固定顺序
  （测试 `M2.2-26`/`M2.2-29`；真机验证脚本也检查文本顺序）。

消费方**不要依赖 JSON 键序**，要按桶名取值。

## 7. 性能没有做压力测试

只保证"仍是**一次** `FindEntities`"这一条硬约束。
没有在几百个实体的极端场景下测过 `Clock` 耗时；`scan.duration_ms` 依赖
`os.clock` 或 `TheSim:GetRealTime`，两者都拿不到时写 `null`（不伪装成 0）。

## 8. 食物白名单是"本构建"的快照

依据本机 `scripts.zip`（build 762172）的 19 种 `FOODTYPE` 定的白名单。
如果游戏更新新增了玩家食物类型，新类型会被判成"不是食物"（fail-safe 方向）。
到时候按同一份依据补白名单即可，测试 `M2.2-05/06` 会盯住回归。

## 9. 观察不是授权（架构性的，不是缺陷）

`pickupables` 里的目标**不代表现在能捡**：距离、背包容量、角色状态、Control Lease
都在执行时重新判。所以模型可能看到"看得见但捡不了"的目标，
这时会拿到 `out_of_range` / `inventory_full` / `actor_*` / `control_denied` 等明确原因。

## 10. 本阶段明确没做的（按任务书要求）

不新增游戏动作；不扩 Pickup 白名单；不砍树/挖矿/采集/制作/建造/战斗/攻击；
不新增宏动作；不做自主生存循环；不新增 Control Lease / Node 服务 / 命令文件；
不做第二次 `FindEntities`；不改用户存档；不改 API Key 与模型配置；
不改归档 A 栈；不改 `m12-watch.mjs`。
