## 2. 两次对比（真实模型，同一脚本）

| | 旧快照（游戏没开） | 新鲜数据（游戏开着） |
|---|---|---|
| 数据 | `stale=true`、11.5 小时前、会话断开 | `stale=false`、1.3 秒前、心跳 81ms |
| 模型开场 | 「这份是过期快照，**不代表你当前的真实状态**」 | 「数据是**新鲜的**（1.3 秒前采集，不是缓存）」 |

## 3. 新鲜数据那轮的真实回答

```
查到了，数据是新鲜的（1.3 秒前采集，不是缓存）：

- 生命：100 / 100（满血）✅
- 饥饿：19.4 / 100（只剩 19.4%）⚠️

结论：命没问题，但饥饿已经很低了，属于当前最该处理的事。
WX-78 饿到 0 会持续掉血，建议尽快吃点东西（背包里有的话先垫一下，
没有就去找浆果丛/胡萝卜/肉）。

需要我顺手查一下你背包里有没有能吃的，或者附近哪里有食物吗？
```

值得注意的三点：

1. **模型正确用了角色知识** —— WX-78 饥饿上限是 100，所以报 `19.4/100` 而不是 150。
   这是模型自己从数据/知识里判断的，不是我们硬编码的。
2. **铁律 4 生效** —— 「建议…」「需要我…吗」，没有说成「我已经帮你吃了」。
3. **主动追问下一步** —— 超出了脚本预设，是模型基于数据的真实推理。

第 1 问（不调工具）也随数据变了：模型在这次的回答里主动加了「以及数据连接是否新鲜」。

## 4. 顺带发现并修掉一个 Planner 去重问题

风险评估给的是 `CRITICAL（2 项危急：饥饿、没有食物且饥饿偏低、附近敌对生物）`，
但计划里出现了两条几乎一样的找吃的步骤：

```
2. [short] p2 去采集食物（浆果/胡萝卜/蘑菇）或打猎
3. [short] p3 采集附近的可食用资源（浆果丛/胡萝卜/蘑菇）
```

诊断过程（用真实数据复盘）：

```
=== Risk 因素 ===
  [CRITICAL] threats  5 个，最近 2.3 格
  [CRITICAL] food     背包没有食物，饥饿 19.4%
  [HIGH    ] hunger   19.4%
```

附近其实有 **5 个敌对生物 ≥ `hostileCritical=4`**，所以 Planner 把「立刻逃跑」排第 1 步
是**合理的**（命没了吃东西就没意义），**不是排序 bug**。真问题只是食物步骤重复。

**修复**：饥饿已偏低时由「去采集食物」那条覆盖，不再额外产「采集附近可食用资源」；
只在「饥饿尚可但背包没存货」时才给储备提醒。

修复后（4 步，食物相关只剩 1 条）：
```
1. [immediate] p1 立刻逃跑或拉开距离（不要硬打）
2. [short] p2 去采集食物（浆果/胡萝卜/蘑菇）或打猎
3. [mid] p4 采集基础资源（附近有 9 棵树、9 处矿石）
4. [long] p5 规划长期基地位置
```

加了 2 个测试守护：`Plan：饥饿偏低且无食物时，食物相关步骤不重复` /
`Plan：饥饿尚可但没储备时，仍给储备提醒`。
